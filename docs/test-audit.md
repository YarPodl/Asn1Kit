# Статический аудит тестов Asn1Kit и сравнение ASN.1 библиотек

Дата: **2026-10-10**. Исследованный HEAD: `1c906a3456dd0d60557a60c84531301851002d6e`. Аудит выполнен по исходникам, без запуска тестов и измерения покрытия.

## Методика и границы

Прочитаны все 51 C# файл трёх тестовых проектов, включая вспомогательные методы и поставщиков данных. Каждый Fact/Theory сопоставлен с вызовами, данными и assert. Из compiler/tests исключены только проверки lexer/parser/AST/IR/schema/options/overlay; методы с генерацией, компиляцией или выполнением C# включены, в том числе смешанные T0271 и T0273.

Охват: Runtime, legacy Asn1Kit.Pkix/Cms/DVCS, modern Asn1Kit.Modern и отдельная группа CMS demo. Synthetic generated C# — мини-модули compiler tests; их проверки не приписываются поставляемым сборкам. RSA и цепочки сертификатов учтены только в demo-сценариях вне ASN.1 матрицы. C++ Runtime вне охвата.

Столбец Asn1Kit объединяет проверки Runtime и generated-кода: берётся самая сильная подтверждённая отметка из включённых проектов. Частичные проверки автоматически не суммируются до «есть». Компонент и область теста сохранены в описи и доказательствах; общий статус не обещает одинаковую глубину проверки каждой сборки. REAL, RELATIVE-OID и полная проверка constraints вне локального профиля.

Методы, строки InlineData/MemberData и сценарии считаются отдельно. Fact даёт один потенциальный вызов xUnit, Theory — число строк данных: всего 551, в основном охвате 462. Внутренние циклы это число не увеличивают; их размеры или причины неопределённости указаны в parameters.csv.

inventory.proof_modes различает текст/golden, компиляцию Roslyn, выполнение кодека, round-trip, независимый эталон и отказ. Сила проверки определяется assert: компиляция не доказывает корректность кодека, а собственный round-trip может воспроизвести общую ошибку encoder/decoder.

| Статус | Правило |
| --- | --- |
| есть | Прямая проверка существенного поведения сценария с ожиданием/данными; не означает все возможные значения. |
| частично | Есть конкретная проверка части условий, иного profile/API или слабый assert; ограничение записано в E. |
| косвенно | Сценарий участвует в более широком тесте, но нужное поле/условие отдельно не assert-ится. |
| не найден | В явно перечисленном обследованном корпусе прямую проверку не нашли; область поиска, запрос и опись файлов сохранены. |
| неприменимо | Иной слой/API, BER для DER-only API либо возможность вне выбранного/поддержанного продукта. |
| не подтверждено | Есть кандидаты/неполное сопоставление или недоступный источник; отсутствие тестов не утверждается. |

Положительные отметки подтверждаются assert, ожиданиями и данными в evidence.csv. Fuzz-target подтверждает только конкретное свойство: отсутствие падения, ret_len≤size или равенство decode→encode→decode.

## Подробные выводы по Asn1Kit

### Runtime: что фактически проверяется

Проверяются BOOLEAN/NULL, INTEGER/BigInteger и фиксированные разрядности, ENUMERATED, OCTET/BIT STRING, OID, 12 форм строк и UTC/GeneralizedTime. Основные assert: точные DER-байты и contents, EOF, исключения повреждённого TLV. Эталон BCL обеспечивает двустороннюю проверку записи/чтения. Корпус отказов ограничен.

Reader по умолчанию принимает неминимальный INTEGER и ненулевые неиспользуемые биты BIT STRING; strict-флаги отвергают их. Неминимальная длина и избыточный OID, наоборот, требуют allow-флагов. Asn1ReaderOptions.Strict не обеспечивает полной валидации DER: constructed-строки принимаются и под DER, как указано в Asn1ConstructedDecoder и backlog.

[T0083](../runtime-csharp/tests/Asn1Kit.Runtime.Tests/PrimitiveCodecTests.cs#L133) и [T0158](../runtime-csharp/tests/Asn1Kit.Runtime.Tests/RuntimeTests.cs#L595) требуют сохранения неминимальных INTEGER contents и длины TLV. WriteRaw/Lazy также сохраняют исходные байты. Каноническая DER-запись относится к encoder числовых значений; raw-пути имеют контракт сохранения.

BER indefinite и простая конкатенация constructed-сегментов проверены. Пробелы: враждебная глубина/размер, вложенные сегменты и неиспользуемые биты промежуточного BIT-сегмента. Защита от переполнения Int32 не ограничивает материализацию; настраиваемых лимитов нет. WriteSequence_DeepNesting проверяет лишь три уровня.

Проверены лексикографическая сортировка DER SET OF и сохранение порядка BER. EnterSet сохраняет порядок полей; generated SET проверяется отдельно. T0199 принимает явно закодированный DEFAULT и исключает его при повторной записи. Строгий отказ DEFAULT и проверка порядка SET OF при DER-чтении требуют решения о политике и реализации.

Владение памятью и состояние API проверяются через исходный массив/смещение, изменение MemoryManager, независимые копии, короткий буфер TryRead, Remaining/повторное чтение, LIFO, копии/устаревшие области и исключения. Тесты аллокаций после прогрева ограничены фабрикой OCTET STRING, TryGetInt32 и сравнением с захватывающим замыканием.

Слабые assert: [T0179](../runtime-csharp/tests/Asn1Kit.Runtime.Tests/RuntimeTests.cs#L1023) сравнивает байты callback без проверки идентичности буфера; [T0180](../runtime-csharp/tests/Asn1Kit.Runtime.Tests/RuntimeTests.cs#L1032) требует только EncodedLength>0; [T0104](../runtime-csharp/tests/Asn1Kit.Runtime.Tests/PrimitiveCodecTests.cs#L392) проверяет очистку/запись без наблюдения ёмкости. Эти сценарии отмечены частично.

Эталон UniversalString — UTF32 big-endian и BCL **raw TLV**, без семантического decoder BCL. Старые наборы символов проверены локально. Пробелы: повреждённые Unicode scalar/surrogate/избыточный UTF8 и неверные календарные даты.

### Generated C#: текст, компиляция и выполнение

Compiler tests проверяют текст/golden, Roslyn Emit, имена/коллизии/алиасы/представления INTEGER, составные типы, DEFAULT, расширения SEQUENCE/CHOICE, OPTIONAL CHOICE без тега, lazy/retained и open types. Встроенные C# проверки if/throw/return учтены в parameters.embedded_CSharp_probe и inventory.embedded_checks.

GeneratedCompilation выбрасывает InvalidOperationException при неуспешном Emit. Golden сравнивает списки и содержимое файлов; 35 modern-модулей и reflection базовых Signed-типов проверяют структуру сборки. Выполнение кодеков сообщений проверяется отдельно.

Open-type tests различают raw Decode и Binding TryDecode: неизвестный ключ сохраняет opaque Any; неверное содержимое известного ключа может остаться raw после Decode, но отвергается при типизированном доступе. Binding общий для modern/legacy. Дескрипторы с совпадающими формой/ключом допускают использование между каталогами в проверенных случаях. T0035 проверяет знаковые/беззнаковые ключи и дубликаты.

Synthetic generated C# проверяет селекторы предка/вложенного пути, отложенный SET, OID/INTEGER keys, дубликаты до decode, criticality/метаданные, lazy/контейнеры значений, inline/nested OF, NULL и DirectoryString CHOICE. Legacy/modern получают отметки только за использование их типов. SIZE/value и unsupported constraints в IR не доказывают исполнение ограничений Runtime.

### PKIX / CMS / DVCS и demo

Legacy: 4 сертификата PKITS DER с эталонными полями, проверками .NET X509 и точной повторной записью. Для 7 семейств расширений — SKI, AKI, KeyUsage, BasicConstraints, CertificatePolicies, NameConstraints, SAN — сверяются criticality, значения и extnValue. SAN использует 3 внешних вектора; GeneralName IP/OID — hex/BCL writer; OtherName XMPP/SRV/SMTPUTF8 — литеральные байты.

GoodCACRL: отозванные записи, время, reason, CRLNumber, AKI и точные байты round-trip. Certificate/CRL проверяются усечением посередине и заменой корня SEQUENCE→SET. Modern использует 3 сертификата DER в ModernRfc и 2 в проверках дескрипторов; подробные эталоны полей legacy не повторяет.

Для поставляемых PKCS10/OCSP/modern attribute certificate и CMS EnvelopedData/AuthenticatedData/CompressedData прямые тесты кодеков сообщений не найдены. DVCS проверяется в legacy; в modern-корпусе он отсутствует.

DVCS legacy: минимальный request, imprint+nonce и error response сравниваются с литеральным DER. DVCSCertInfo проверяет корень, отдельные поля и собственный round-trip; внешний эталон не установлен. Для request проверяются неверный корень и усечение.

CMS demo: 20 методов (14 CmsDemoTests, 6 CmsModernDemoTests). Attached SignedData создана .NET SignedCms с собственным сертификатом, без RFC-фикстуры. Recording verifiers проверяют передачу входных данных; RSA/цепочки остаются вне ASN.1 матрицы.

SignedAttrs: universal SET tag31 и сохранённые contents, без независимого эталона полной сортировки. Проверены сертификат/SKI подписанта, обязательные поля/digest algorithms, повреждённый CMS/остаток ввода, байты issuer и ошибки CLI. Пробелы: detached, несколько подписантов, BER indefinite CMS и recipientInfo. Educational sign проверяет структуру через инспектор; заглушка не подтверждает подпись.

[docs/status.md](status.md) и [pkix-test-backlog.md](pkix-test-backlog.md) сопоставлены с исходниками. Demo закрывает часть CMS backlog; полный корпус, канонические SignedAttrs и сообщения RFC остаются открытыми.

### Что дают внешние примеры

Ориентиры P0: Botan проверяет размер 5/4 байта, отключение лимита и глубину EOC 16/constructed-строк 2; pyasn1 — отказ на 200 вложениях, принятие 50 уровней/200 соседей и отсутствие RecursionError на 50000 вложениях; rasn — ExceedsMaxParseDepth; Go — границы глубины и аллокации ≤20 MiB для повреждённой 10 MB DER-бомбы.

Различия политик: OpenSSL ASN1_EMBED принимает пустой INTEGER как 0; Mbed get_int отвергает отрицательные значения, MPI принимает пустой INTEGER как 0. Parser времени rasn использует границу 70/69, локальные Asn1Kit/BCL — 50/49.

Примеры для расширения тестов: RFC4134 CMS Bouncy Castle, поля CSR/OCSP/CMS/сертификатов asn1crypto, пустая CRL rasn, строгий DEFAULT Botan и проверка порядка SET OF System.Formats.Asn1.
