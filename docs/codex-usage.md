# Экономное использование Codex

Этот файл предназначен для разработчиков и не входит в обязательный контекст каждой задачи.

## Формулировка задачи

Указывай результат, область и проверку. Для локальной задачи полезен короткий шаблон:

```text
Исправь <поведение> в <каталог или проект>.
Не исследуй остальные слои, пока тест или зависимость не укажет на них.
Добавь регрессионный тест и запусти dotnet test Asn1Kit.sln.
Ответ — краткий.
```

- Один thread используй для одной связной задачи; новую тему начинай в новом.
- Сразу называй известный файл, тест или исключение.
- Не проси читать всю документацию: `AGENTS.md` и вложенные инструкции маршрутизируют к нужному playbook.
- Не подключай web, плагины или внешние приложения для чисто локальной задачи.
- Не проси отдельный план для небольшой однозначной правки.

## Модель и reasoning

- Низкий effort подходит для локальных механических правок, поиска и обновления документации.
- Средний — базовый выбор для реализации и обычной диагностики.
- Высокий используй для parser/IR semantics, BER/DER, сложной отладки и межслойного дизайна.
- Не меняй модель или effort внутри связной серии шагов без причины: это ухудшает повторное использование prompt cache.

Уровень reasoning выбирается для конкретной задачи; проект не фиксирует его в `.codex/config.toml`.

## Контекст, поиск и индекс

- Начинай с `rg` в затронутом каталоге, а не с обхода всего репозитория.
- Golden JSON и generated C# исключены из семантического индекса через `.cursorindexingignore` и из обычного поиска `rg` через `.ignore`, но остаются доступными по явному пути, с `rg --no-ignore` и через diff.
- Отдельный vector index проекта не поддерживается: структура каталогов, вложенные `AGENTS.md` и `rg` дают актуальный результат без устаревающей копии кода.
- Большой generated-файл открывай только при диагностике конкретного типа или проверке diff.

## Prompt cache

Prompt cache управляется клиентом и сервисом, а не файлами репозитория. Для лучшего reuse:

- сохраняй корневые инструкции и набор инструментов стабильными;
- добавляй изменчивые детали в запрос, а не в `AGENTS.md`;
- продолжай существующий thread для связной работы;
- после смены темы начинай новый thread вместо переноса длинной истории;
- оценивай не только cache hit, но и общий размер входного контекста.

Кеш уменьшает стоимость обработки совпавшего префикса, но длинный префикс всё равно занимает контекстное окно.

## Повторяемые workflow

Используй существующие playbook для проектирования и скрипты для механики:

- конструкция ASN.1 — `compiler/docs/playbooks/compiler-construct.md`;
- новый kind IR — `compiler/docs/playbooks/new-ir-kind.md`;
- C# backend — `compiler/docs/playbooks/csharp-backend.md`;
- runtime — `runtime-csharp/docs/playbooks/runtime.md`;
- регенерация — `scripts/regenerate-*.ps1`.

Repository skills отдельно не дублируют эти материалы: короткие вложенные `AGENTS.md` обеспечивают маршрутизацию, а playbook загружается только для соответствующей работы.
